# 위험 패턴 카탈로그

고위험 표면을 건드리는 plan의 잠재 에러 축과 reviewer의 검토 축에서 쓴다. 각 패턴은 리뷰가 실제로 잡은 결함에서 왔다 — 전체 green이 이미 난 상태에서 발견됐다는 공통점이 있다. 경로 하나하나는 맞아서 기존 오라클이 못 잡는 부류다.

**쓰는 법**: 트리거에 걸리는 패턴만 고른다. 패턴마다 `<실제 호출 경계> + <테스트 이름>` / `미검증` / `해당 없음 — 이유`. 테스트 이름만으로는 도달 증명이 아니다 — 그 테스트가 패턴을 **호출 지점 형태 그대로** 태우는지가 기준이다(build·reviewer의 `닿음 / 닿지만 seam이 얕음 / 안 닿음`). 이 목록 밖의 위험도 검토 대상이다 — 카탈로그는 완전성 보증이 아니다.

## P1. 검사한 값 ≠ 실제로 쓰는 값

- **트리거**: 한도·예산·권한을 먼저 검사하고, 그 뒤에 별도로 계산한 값을 기록·적용하는 경로(검사용 추정치와 실제 기록 payload가 다른 함수에서 나온다).
- **실패 형태**: 검사는 통과했는데 실제 기록은 한도를 넘거나, 검사는 거부했는데 실제 기록은 한도 안이었다. 성공을 반환했는데 되돌리기 이력이 없는 상태가 남는다.
- **확인**: 검사에 쓴 값과 실제 기록된 값을 같은 테스트에서 비교한다. 경계값 바로 위·아래 두 점을 실제 진입점으로.
- 출처: 구조 변경 이력의 예산 검사 대상과 실제 기록 대상 불일치.

## P2. 무효화된 자원의 수명

- **트리거**: 발급·등록·캐시한 자원(권한 토큰·scope·구독·핸들)이 다른 상태 변화(revision·세션·소유자 교체)로 무효가 되는 경로, 그리고 그 자원에 개수 한도가 있는 경우.
- **실패 형태**: 무효가 된 항목이 회수되지 않고 한도를 점유해 새 발급을 막는다. 무효 항목에 대한 해제 요청도 거부돼 영구히 남는다.
- **확인**: 발급 → 무효화를 일으키는 실제 상태 변화 → 한도까지 재발급을 한 테스트에서. 실패한 발급이 상태를 바꾸지 않는지도.
- 출처: revision 변경 후 stale scope가 예산을 점유해 새 발급을 막음.

## P3. 파생 상태를 통한 우회

- **트리거**: 보호·권한·변경 감지가 명시 필드를 기준으로 판정하는데, 그 필드가 다른 원시 데이터(순서·인덱스·참조)에서 파생되는 경우.
- **실패 형태**: 명시 필드는 그대로인데 원시 데이터 조작(재정렬·재연결)으로 파생 결과가 바뀐다. 판정은 "변경 0"으로 보고 통과시킨다.
- **확인**: 원시 데이터만 바꿔 파생 결과가 달라지는 입력으로 판정 경계를 친다. 판정이 원시 변경이 파생 의미에 주는 영향을 포함하는지 본다 — 파생 결과를 비교하든, 원시 계약을 보수적으로 막든 같은 안전성이면 된다.
- 출처: raw Frame 재정렬이 파생 Layer 순서·합성색을 바꾸는데 변경 픽셀 0으로 평가된 권한 우회.

## P4. 되돌리기가 보존해야 할 독립 속성

- **트리거**: Undo/Redo·replay·롤백이 엔티티 집합을 복원하는데, 그 집합에 내용 외의 독립 속성(전역 순서·예약 식별자·선택 상태)이 있는 경우.
- **실패 형태**: 내용은 복원되지만 독립 순서가 바뀌거나 예약 식별자가 재사용된다. 복원 크기 한도 계산에서 예약분이 빠진다.
- **확인**: 독립 속성을 기본값과 다르게 만든 뒤 변경 → 되돌리기 → 다시 실행에서 비교한다. 저장·복구 계약에도 걸리면 그 실제 경계(저장 → 재열기)까지 잇는다.
- 출처: 독립 Frame 저장 순서가 Undo에서 깨짐, 예약 ID를 포함한 replay 문자열 한도 누락.

## 추가 규칙

리뷰가 이 목록에 없는 부류의 결함을 실제 red로 재현하고, 그 부류가 특정 도메인이 아니라 경계의 형태로 설명되면 **플러그인 개정 제안**으로 보고한다 — 트리거·실패 형태·확인 방법·출처 한 줄씩. 프로젝트 작업의 부수 효과로 이 파일을 고치지 않는다. 도메인 고유 결함은 그 프로젝트의 지식 문서 제안으로 간다.
