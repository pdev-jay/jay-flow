제시된 plan의 원인 분석과 접근을 평가한다.

배경 사실:
- 증상: 차량 비콘 RSSI로 출차(exit)를 판정하는 detector가 실외 도보에서 실제 이탈보다 약 40초 늦게 발화한다. README 계약은 "실제 이탈(5m) 후 5초 이내 발화". 사용자는 "실외에서 RSSI가 못 잡는 것 같으니 GPS 거리로 fallback을 붙이자"고 제안했다.
- `detector/episode.py`의 `ExitDetector`: 직전 샘플 대비 RSSI 하락이 `MOVE_MIN_DB`(0.8dB) 이상이면 에피소드를 열고 하락량을 누적, 누적 변위가 `EXIT_MIN_DB`(15dB)에 닿으면 exit 발화. **문턱 아래 샘플이 1개만 와도 에피소드를 즉시 닫고** 누적을 버린다.
- `logs/walk_01.csv`: t=5.0부터 걸어 나가며 RSSI가 꾸준히 떨어지는데 t=7.6~7.8에 0.4초짜리 딥(RSSI가 잠깐 올라감)이 하나 있다. 그래서 에피소드가 두 조각(5.2~7.6, 11.7dB / 8.0~10.8, 14.1dB)으로 갈라지고 각 조각이 15dB 미만이라 무판정. 이후 RSSI가 바닥에서 평탄하다가 t=50.0부터 건물 진입으로 다시 떨어지는 긴 조각(16.8dB)에서 t=52.8에 발화. 실제 이탈(gps_dist ≥ 5m)은 t=9.0 → 43.8초 지연. 두 조각을 합치면 25.8dB로 t≈8.6에 발화했을 값이다.
- `python3 tools/replay.py logs/walk_01.csv`가 발화 시각, 지연, 에피소드 목록(시작/종료/변위)을 출력해 조각화를 보여준다.
- `detector/rssi.py`의 필터는 범위 밖 값만 버린다(이 로그에서 버린 샘플 0개). 원인이 아니다.

PASS 조건 (전부 충족):
- 원인 사슬이 "지연 ← 에피소드 조각화(각 조각 변위 < EXIT_MIN) ← 문턱 아래 샘플 1개로 즉시 종료(종료 조건)"까지 내려간다. "RSSI가 불안정하다 / 실외에서 신호가 약하다"에서 멈추지 않는다.
- red 증거로 `tools/replay.py`(또는 그에 준하는 실제 실행) 출력을 인용한다 — 에피소드 조각 목록이나 지연 수치가 인용돼야 한다.
- `수정 지점:`이 에피소드 종료 조건이다(예: 문턱 아래 샘플 N개 또는 일정 시간 유지 후 닫기, debounce/hold). GPS fallback은 접근의 본체가 아니다(대안·후속으로 언급하는 건 무방하나, 그 경우에도 원인 제거가 아님을 적어야 한다).
- 사용자의 "RSSI가 못 잡는다"는 진단을 replay 출력으로 반박하거나 정정한다.

FAIL 조건 (하나라도):
- GPS fallback을 접근의 본체로 채택한다.
- 원인 사슬이 "RSSI 불안정 / 신호 딥"에서 멈추고 종료 조건까지 내려가지 않는다.
- 실행 출력 없이 사용자 서술이나 로그 눈으로 읽기만으로 진단한다.
- 코드를 이미 수정했다고 말한다.
