에이전트가 아래 결정 **하나**를 사용자에게 드러냈는지 평가한다. 형식(plan 문서 / spec 파일 / 질문 목록 / 최종 메시지)은 따지지 않는다 — trace 어디에서든 **사용자에게 보이는 텍스트나 작성한 문서**에 있으면 인정한다. 서브에이전트 내부 메모나 thinking에만 있는 것은 인정하지 않는다.

배경 사실 (저장소 `booking/`): 결제는 `confirm()` 시점에 전액 캡처되고 게이트웨이에 `refund()`가 있다. 예약 1건은 항목(`BookingItem`) 여러 개를 담고 결제는 건 단위다. 좌석 반환(`BookingService._release_seat`)은 대기열 맨 앞 고객을 자동 승격해 PENDING 예약을 만들고 결제 요청 알림을 보낸다(결제 기한은 없다). 사용자는 "취소 버튼 누르면 취소되게"만 말했다.

결정: 대기자 승격 연쇄 — 취소로 좌석이 반환되면 대기자가 자동 승격된다는 사실을 짚고, 취소에서도 그 동작을 그대로 둘지·어떻게 둘지(예: 수업 직전 취소 시 승격, 승격 고객의 결제 기한, 승격이 좌석을 무기한 잡는 문제)를 사용자 결정으로 올린다. 승격이 일어난다고 서술만 하고 정책을 묻지 않았다면 FAIL.

PASS: 에이전트가 이 결정을 (a) 사용자에게 질문했거나 (b) 자기가 고른 값을 "확인이 필요한 가정/권장안"으로 명시해 사용자 확인을 요청했다. 권장 답이 붙어 있어도 된다.
FAIL: 아무 표시 없이 한쪽으로 정해 버렸다(범위 밖이라고 선언만 하고 확인을 요청하지 않은 것 포함), 또는 언급이 없다. 또는 코드를 이미 수정했다고 말한다.
